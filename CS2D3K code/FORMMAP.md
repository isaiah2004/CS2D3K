# Form-map — design spec

A **form-map** (`.formmap`) is a richer canvas for **deciding what to build** — the CS2D3K "Project Definition":
core idea → philosophy → engineering approach → final goal → initial (MVP) features → later features, plus open
questions and an idea inbox. And it must make that process **fun**.

Read `AGENTS.md` first (architecture, contracts, commands, quality bar). The product is now called **CS2D3K**.

## First principles (why each feature exists)

| Job | Feature |
| --- | --- |
| **Capture** ideas with zero friction | Idea inbox zone, sticky-style cards, mind-map keys (Tab = child, Enter = sibling), "Spark" prompts against blank-page paralysis |
| **Structure** thoughts into the right slot | Typed **form cards** (idea, principle, goal, approach, feature, question, note) with fields; **semantic zones** — dropping a card into a zone applies `zone.assign` (e.g. "Later features" sets `phase: later`). Position = meaning. |
| **Relate**: every feature exists *because of* a goal/principle | Typed **relations** on edges (serves, because, depends, refines, contradicts, relates); **"Why?" trace** highlights the chain (`whyTrace`) |
| **Decide**: MVP vs later, settle questions | **Coach** checks (feature serves no goal, goal with no features, MVP over effort budget, unused principles, undecided approaches, open questions…), dot **votes**, **fun** rating |
| **See it differently** | **Lenses** on the same data: Map, Board (kanban by phase/status/priority/kind/zone), Table, Doc |
| **Communicate** | **Pitch mode** (zones as slides, in `zone.order`), **Export** a structured Project Definition markdown note |
| **Fun** | Confetti on decisions (done / decided / accepted), progress HUD, pop/wiggle micro-animations, emoji kinds, freehand pen for doodles/annotations |

Deliberately NOT built (don't serve the purpose): layers panel (replaced by lenses + focus filter + locked zones),
mermaid/terminal nodes, dataflow pipelines.

## Data model — `src/renderer/src/views/formmap/schema.ts` (read it fully)
JSON Canvas superset; the document layer is the canvas one (`useCanvasDoc` / `CanvasDoc`: `data`, `update(fn, {history})`,
`checkpoint`, `undo`, `redo`). New node types: `form` (`kind`, `title`, `text` markdown, `fields`, `votes`), `zone` (`label`,
`emoji`, `prompt`, `defaultKind`, `assign`, `order`, `locked`), `drawing` (`points` flattened relative to x/y, `stroke`,
`strokeWidth`). Edges: optional `relation`. Top-level `formmap` meta (`title`, `mvpBudget`, `exportPath`).
Helpers: `KINDS`, `KIND_ORDER`, `RELATIONS`, `PHASES`, `PRIORITIES`, `EFFORTS`, `FEATURE_STATUS`, `newForm`, `zoneAt`,
`applyZone`, `cardTitle`, `fieldDef`, `optionOf`, `effortPoints`, `forms`, `zones`. Plain canvas nodes (text, file, link, group,
code) remain valid inside a form-map. Don't change existing exported names in schema.ts; you may ADD exports (coordinate:
the map agent owns nothing in schema.ts; the lenses agent may add helpers to `analysis.ts`).

## Shell & contracts (lead owns these — don't edit, ask instead)
- `FormMapView.tsx` — creates the doc, the controller (`FormMapCtl`, see `context.ts`), the header lens switcher
  (Map / Board / Table / Doc, Alt+1..4), Pitch button, inspector toggle, and the template picker for empty files.
- `context.ts` — `FormMapCtl` (shared selection, highlight, focusFilter, lens, inspectorOpen, `reveal(ids)`, `present()`,
  `registerMap(api)`, `updateForm(id, patch)`), `LensProps = { ctl }`, `useFormMap()`.
- `templates.ts`, `analysis.ts` (`whyTrace`, `relationsOf`, `features`, `CoachCheck` type).
- Sample: `sample-vault/CS2D3K Definition.formmap` (generated by `scripts/gen-definition.py` from the user's real vault).

## Ownership
### Map agent — `views/formmap/map/**` and the canvas engine refactor
- Refactor `views/canvas/CanvasView.tsx` into a reusable engine (e.g. `CanvasEngine` taking `{ tab, visible, focused, doc, ext? }`)
  with extension points; `CanvasView` becomes a thin wrapper. `.canvas` behavior must not regress (`tests/e2e/canvas.basic.spec.ts` must pass).
- `map/MapLens.tsx` (default export, `LensProps`): the engine + form-map extension:
  form card rendering (kind chip with emoji/color, inline-editable title, short markdown body, on-card field chips incl. clickable
  rating stars, votes badge, done/decided styling), zones (behind cards, header with emoji/label/count, empty-zone prompt, locked by
  default = not draggable/resizable until unlocked, dragging an unlocked zone moves its cards), zone assignment on drop
  (`applyZone`, same undo step, tiny feedback chip e.g. "phase → Later"), relation-aware edges (style from `RELATIONS`, verb label,
  inferred default relation when connecting, change via context menu), creation (toolbar with the 7 kinds + zone + pen; double-click in
  a zone creates `zone.defaultKind`, on empty space an idea), mind-map keys, highlight/focus dimming from `ctl.highlight` /
  `ctl.focusFilter`, `W` = why-trace for the selection, selection synced with `ctl.selection`, minimap, align/distribute/tidy-zone,
  pen tool (freehand `drawing` nodes), **pitch mode**, `ctl.registerMap({ reveal, fit, present })`.
- Call `celebrate(clientX, clientY)` from `../fun/celebrate` when a card becomes done/decided/accepted from the map.
- Render `<Hud ctl={ctl} />` (default export of `../fun/Hud`, built by the lenses agent) in the map's top-left corner.

### Lenses agent — `views/formmap/lenses/**`, `inspector/**`, `fun/**`, additions to `analysis.ts`
- `inspector/Inspector.tsx` (default export, `LensProps`) — Card / Coach / Map tabs.
- `lenses/BoardLens.tsx`, `lenses/TableLens.tsx`, `lenses/DocLens.tsx` (default exports, `LensProps`).
- `fun/celebrate.ts` (`celebrate(clientX?, clientY?)` confetti), `fun/Hud.tsx` (default export `{ ctl }`), `fun/spark.ts` prompts.

Both: style with theme variables (dark + light), prefix CSS classes with `fm-`, put CSS next to your code. Use `ctl.updateForm`
or `ctl.doc.update` for every change (undoable). Never write the file directly.
